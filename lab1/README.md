# Лабораторная работа №1 — взаимодействие программ: события, запуск процессов, IPC и мониторинг

Курс «Системное программное обеспечение», 2026 год. Вариант 3 — **изменение цвета фона**.

Репозиторий содержит три программы (A, B, C), работающие в связке: одна рисует изображение на экране и меняет его при нажатии клавиш, вторая запускает её с нужными параметрами и отправляет ей команды, третья следит за работой первой, ведёт собственный лог и «инжектирует» дополнительные команды.

> [!IMPORTANT]
> Код в этом репозитории пишется **без использования агентных ИИ** — см. [CONTRIBUTING.md](CONTRIBUTING.md). Исключения: `README.md`, `CONTRIBUTING.md` и лицензионные правки в коде. Каждый запрос на слияние проходит проверку понимания кода автором.

## Компоненты

### Программа A — `program_a`

Интерактивное консольное приложение: меняет цвет фона терминала по нажатию клавиш и по командам из именованного канала (FIFO), ведёт лог событий. Начальный цвет задаётся параметром командной строки; если параметр не передан, используется значение по умолчанию. Команды из FIFO обрабатываются так же, как нажатия клавиш.

**Параметры командной строки**

| Аргумент         | Описание                                                        | По умолчанию |
| ---------------- | --------------------------------------------------------------- | ------------ |
| `--color <name>` | начальный цвет фона: `black`, `red`, `green`, `yellow`, `blue`  | `black`      |

**Управление с клавиатуры**

| Клавиша  | Действие                                                       |
| -------- | -------------------------------------------------------------- |
| `d`      | фон — чёрный                                                   |
| `r`      | фон — красный                                                  |
| `g`      | фон — зелёный                                                  |
| `y`      | фон — жёлтый                                                   |
| `b`      | фон — синий                                                    |
| `q`, `Q` | выход: в лог пишется `exit`, цвет терминала восстанавливается  |

**Внутреннее устройство**

- терминал переводится в неканонический режим через `termios` (`~ICANON`, `~ECHO`), символы читаются по одному;
- цвет фона задаётся ANSI/OSC-последовательностью `\033]11;#RRGGBB` (требуется современный эмулятор терминала с поддержкой OSC 11); при выходе посылается `\033]111` — возврат цвета терминала по умолчанию;
- в фоновом потоке открывается FIFO `/tmp/program_a_fifo` (неблокирующее чтение) и через `poll` ожидаются команды; команда `key=<символ>` обрабатывается как нажатие клавиши; при обрыве связи с писателем канала поток не завершается — программа ждёт нового подключения;
- каждое событие дописывается в лог `program_a.log` в текущем каталоге (см. [Формат логов](#формат-логов)).

Статус: реализованы цикл событий, клавиши, смена цвета, разбор аргументов, лог, приём команд `key=` из FIFO и устойчивость к обрыву связи; команда `cmd=color:<имя>` — в планах.

### Программа B — `program_b`

Пульт управления программой A: сама запускает её и отправляет ей команды из другого терминала.

- находит `program_a` рядом со своим исполняемым файлом (через `/proc/self/exe`) и запускает её в окне alacritty (`posix_spawn`);
- следит за процессом A (`waitpid` с `WNOHANG`) и завершается с сообщением, если A умерла;
- переводит терминал в неканонический режим (`termios`, общий модуль Terminal), читает клавиши по одной и отправляет их в A командой `key=<символ>` через FIFO;
- при ошибках IPC (например, нет читателя канала) печатает сообщение и завершается — без зависаний;
- `q`/`Q` — выход (в A не отправляется).

По заданию также планируются: поля для ввода параметров A (в варианте 3 — цвет фона) и передача их при запуске, отправка команды `cmd=color:<имя>`.

Статус: запуск A, слежение за процессом и отправка команд через FIFO реализованы; поля ввода параметров — в планах.

### Программа C — `program_c`

Программа мониторинга программы A:

- определяет, какая клавиша была нажата и когда (по логу `program_a.log`);
- убеждается, что следит именно за программой A: сверяет имя процесса (`/proc/<pid>/comm`) и командную строку (`/proc/<pid>/cmdline`);
- пишет собственный лог `program_c/program_c.log` со временем запуска и завершения программы A;
- «инжектирует» дополнительные команды: при нажатии выбранной клавиши отправляет в FIFO дополнительную команду, и одно нажатие в A приводит к дополнительному действию;
- корректно переживает ситуации «A ещё не запущена», «A уже завершилась», «лог пуст», «FIFO недоступен»: понятное сообщение и продолжение работы.

Статус: в разработке (заглушка). Для Windows по заданию потребуется отдельный скрипт `program_c.au3` (AutoIt).

## Архитектура взаимодействия

Взаимодействие программ в Linux: запуск процесса, именованный канал (FIFO) и файловые логи. Мониторинг — через `/proc`.

```text
program_b ── запуск с параметрами ──► program_a
program_b ── команды ──────────────┐
program_c ── инъекция ─────────────┴► FIFO /tmp/program_a_fifo ──► program_a
program_c ── мониторинг (/proc/<pid>) ────────────────────────────► program_a
program_a ── program_a.log ──────────────────────────────────────► program_c (чтение событий)
program_c ── program_c.log (время запуска и завершения A)
```

Сейчас работают: запуск A из B (`posix_spawn` + alacritty), отправка клавиш из B в FIFO, приём команд `key=` и устойчивость к обрыву связи в программе A. Остались: передача параметров A из B и программа C (мониторинг `/proc`, инъекция команд); актуальное состояние — в разделе [Статус реализации](#статус-реализации).

## Требования

- **Linux** — текущая реализация использует POSIX-механизмы (`termios`, FIFO); мониторинг через `/proc` и варианты для Windows — по заданию в планах (Win32 API, AutoIt).
- **CMake ≥ 3.21** — из-за версии схемы `CMakePresets.json` (version 3).
- **Компилятор с C++20**: GCC 13+ или Clang 17+ (требуется `std::format`).
- **Ninja** — генератор для пресетов сборки.
- **alacritty** — эмулятор терминала, в котором программа B запускает A (путь `/usr/bin/alacritty` зашит в коде). Для ручного запуска A не требуется.
- Опционально: `clang-format` (форматирование), `clangd` (навигация по коду — `.clangd` уже указывает на `out/gcc-debug`).

## Сборка

Все команды выполняются из каталога `lab1`.

### Linux — через пресеты (рекомендуется)

```bash
# Debug-сборка (GCC + Ninja)
cmake --preset gcc-debug
cmake --build out/gcc-debug

# Release-сборка (Clang + Ninja)
cmake --preset clang-release
cmake --build out/clang-release
```

Сборка отдельной цели: `cmake --build out/gcc-debug --target program_a`.

После сборки исполняемые файлы лежат в `out/<preset>/bin/` (каталог задаётся через `CMAKE_RUNTIME_OUTPUT_DIRECTORY`).

### Linux — вручную

```bash
cmake -S . -B out/manual -DCMAKE_BUILD_TYPE=Debug
cmake --build out/manual
```

### Windows

Пока не поддерживается. По заданию для Windows планируются: оконный вариант программы A (Win32 API, обработка `WM_KEYDOWN`), `CreateProcess`/`WM_COPYDATA` в программе B, скрипт `program_c.au3` для программы C; сборка через CMake с MSVC или MinGW-w64.

## Запуск

### Программа A (ручной запуск)

Запускать из каталога `lab1`: лог `program_a.log` создаётся в текущем каталоге.

```bash
cd lab1
mkfifo /tmp/program_a_fifo 2>/dev/null   # канал должен существовать до старта A
./out/gcc-debug/bin/program_a                # фон по умолчанию (чёрный)
./out/gcc-debug/bin/program_a --color green  # старт с зелёным фоном
```

Нажимайте `d`/`r`/`g`/`y`/`b` для смены цвета фона, `q` — выход. Программа работает в цикле событий: ждёт событие (клавишу или команду из FIFO), обрабатывает, обновляет экран, снова ждёт. FIFO открывается один раз при запуске — если канал не существовал в этот момент, приём команд работать не будет. Если писатель канала отключится (например, B завершится), A продолжит работу и примет новое подключение.

### Программа B (запускает A сама)

```bash
cd lab1
mkfifo /tmp/program_a_fifo 2>/dev/null   # канал должен существовать до старта A
./out/gcc-debug/bin/program_b
```

B находит `program_a` в своём каталоге (`out/gcc-debug/bin/`) и открывает её в окне alacritty. Клавиши `d`/`r`/`g`/`y`/`b`, нажатые в B, меняют цвет фона в A; `q`/`Q` — выход из B. Если A завершилась (например, `q` внутри A), B сообщит об этом и завершится; если читателя FIFO нет, B напечатает ошибку вместо зависания.

### Программа C

В разработке (заглушка). Планируемый порядок взаимодействия — см. [Демонстрационный сценарий](#демонстрационный-сценарий).

## Формат логов

**`program_a.log`** (создаётся в текущем каталоге; при запуске из `lab1` — `lab1/program_a.log`) — по одной строке на событие:

```text
2026-10-19 19:20:20 key=r
2026-10-19 19:20:24 key=y
2026-10-19 19:20:28 key=b
2026-10-19 19:20:31 exit
```

Формат строки: `ГГГГ-ММ-ДД ЧЧ:ММ:СС key=<клавиша>`. При завершении программы дописывается строка `ГГГГ-ММ-ДД ЧЧ:ММ:СС exit`.

Клавиши, полученные через FIFO, обрабатываются и логируются так же, как нажатые локально, — по логу источник не отличается. Клавиши вне набора `d`/`r`/`g`/`y`/`b` игнорируются.

**`program_c/program_c.log`** — в разработке; будет содержать время запуска и завершения программы A.

## Протокол команд (FIFO)

Для управления программой A из других процессов используется именованный канал `/tmp/program_a_fifo`. Программа A держит его открытым (неблокирующее чтение в фоновом потоке, ожидание через `poll`); пришедшие команды обрабатываются так же, как нажатия клавиш.

Команды — текстовые, по одной на сообщение:

| Команда            | Действие                                                          | Статус          |
| ------------------ | ----------------------------------------------------------------- | --------------- |
| `key=<символ>`     | обрабатывается как нажатие клавиши (например, `key=b` — синий фон) | ✅ реализовано   |
| `cmd=color:<имя>`  | смена цвета по имени (например, `cmd=color:blue`)                  | ⏳ в планах      |

Пример отправки команды из оболочки (программа A должна быть запущена):

```bash
mkfifo /tmp/program_a_fifo 2>/dev/null
echo -n 'key=b' > /tmp/program_a_fifo
```

Канал должен существовать к моменту запуска A: программа открывает FIFO один раз при старте (см. [Запуск](#запуск) — во всех сценариях канал создаётся заранее). Программа B тоже создаёт канал при отправке, если его нет, но если A уже стартовала без канала, команды не будут приниматься. Если читателя канала нет, B печатает ошибку и завершается — не зависает; A же переживает отключение писателя и ждёт новое подключение. Неизвестные команды и сообщения с неподдерживаемым форматом игнорируются.

## Демонстрационный сценарий

1. Запускается программа C — она наблюдает за появлением программы A.
2. Запускается программа B.
3. Из B запускается A с параметрами (например, `--color blue`).
4. B отправляет A команду через FIFO.
5. C логирует нажатия клавиш, время запуска и завершения, инжектирует дополнительную команду.
6. A завершается (`q`), C фиксирует завершение в `program_c.log`.

Сейчас выполнимы: запуск A из B (пока без параметров), отправка команд через FIFO, завершение A и выход из B. Программа C (шаги 1, 5, 6) и передача параметров A при запуске — в разработке.
