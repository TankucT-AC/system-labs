Курс «Системное программное обеспечение», 2026 год. Вариант 3 — **изменение цвета фона**.

Три программы для Linux работают в связке: **A** меняет цвет фона терминала по клавишам и по командам из именованного канала, **B** запускает A и управляет ею из другого терминала, **C** следит за A через `/proc`, ведёт собственный лог и «инжектирует» дополнительные команды. Связь — FIFO, мониторинг — `/proc`, события — файловые логи.

## Быстрый старт

```bash
cd lab1
cmake --preset gcc-debug && cmake --build out/gcc-debug
```

```bash
# терминал 1: B запускает A в окне alacritty и подключается к каналу
./out/gcc-debug/bin/program_b

# терминал 2: C находит A, пишет program_c.log и инжектирует команды
./out/gcc-debug/bin/program_c
```

В терминале с B нажимайте `d`/`r`/`g`/`y`/`b` — цвет фона в A меняется. Нажатие `b` дополнительно вызывает инъекцию: C видит строку `key=b` в логе A и отправляет в канал `key=d`. Выход: `q` в A, затем `q` + Enter в C.

## Возможности

- **Смена цвета фона** из кода через OSC 11 (`\033]11;#RRGGBB`) в неканоническом режиме терминала.
- **Событийный цикл** в A: клавиатура и фоновый поток чтения FIFO работают одновременно; доступ к терминалу защищён мьютексом.
- **IPC через именованный канал** `/tmp/program_a_fifo`: текстовые команды `key=<символ>`.
- **Устойчивость к обрыву связи**: A переживает отключение писателя, B — отключение читателей (`EPIPE`).
- **Запуск процесса из процесса**: B находит A рядом со своим бинарником и запускает её в alacritty через `posix_spawn`.
- **Мониторинг через `/proc`**: C находит A по `comm`, проверяет `cmdline` и ждёт её завершения.
- **Логи**: `program_a.log` (события A) и `program_c.log` (время запуска и завершения A).
- **Инъекция команд**: C дочитывает новые строки лога A и отправляет в канал дополнительную команду.

## Компоненты

### Программа A — `program_a`

Интерактивное консольное приложение: меняет цвет фона терминала по нажатию клавиш и по командам из именованного канала (FIFO), ведёт лог событий. Начальный цвет задаётся параметром командной строки; если параметр не передан, используется значение по умолчанию. Команды из FIFO обрабатываются так же, как нажатия клавиш.

**Параметры командной строки**

| Аргумент         | Описание                                                        | По умолчанию |
| ---------------- | --------------------------------------------------------------- | ------------ |
| `--color <name>` | начальный цвет фона: `black`, `red`, `green`, `yellow`, `blue`  | `black`      |

**Управление с клавиатуры**

| Клавиша  | Действие                                                       |
| -------- | -------------------------------------------------------------- |
| `d`      | фон — чёрный                                                   |
| `r`      | фон — красный                                                  |
| `g`      | фон — зелёный                                                  |
| `y`      | фон — жёлтый                                                   |
| `b`      | фон — синий                                                    |
| `q`, `Q` | выход: в лог пишется `exit`, цвет терминала восстанавливается  |

**Внутреннее устройство**

- терминал переводится в неканонический режим через `termios` (`~ICANON`, `~ECHO`), символы читаются по одному;
- цвет фона задаётся ANSI/OSC-последовательностью `\033]11;#RRGGBB` (требуется современный эмулятор терминала с поддержкой OSC 11); при выходе посылается `\033]111` — возврат цвета терминала по умолчанию;
- смена цвета вызывается из двух потоков (главный цикл и поток FIFO), поэтому `Terminal::updateTerminalColor()` защищён мьютексом;
- в фоновом потоке открывается FIFO `/tmp/program_a_fifo` (неблокирующее чтение, повтор `open` при `EINTR`) и через `poll` ожидаются команды; при обрыве связи с писателем канала поток не завершается — программа ждёт нового подключения;
- разбор команды вынесен в общий модуль `utils` (`utils::keyMessageParser`), команда `key=<символ>` обрабатывается как нажатие клавиши;
- каждое обработанное событие дописывается в лог `program_a.log` в текущем каталоге (см. [Формат логов](#формат-логов)); при старте пишется строка `key=` — это применение начального цвета.

Статус: реализованы цикл событий, клавиши, смена цвета, разбор аргументов, лог, приём команд `key=` из FIFO и устойчивость к обрыву связи; команда `cmd=color:<имя>` — в планах.

### Программа B — `program_b`

Пульт управления программой A: запускает её, создаёт канал и отправляет команды из другого терминала.

- игнорирует `SIGPIPE`: если все читатели канала отключились, `write` возвращает `EPIPE`, B печатает сообщение и завершается;
- находит `program_a` рядом со своим исполняемым файлом (через `/proc/self/exe`) и запускает её в окне alacritty (`posix_spawn`); проверяет, что файл существует, и сообщает об ошибке запуска;
- создаёт FIFO `/tmp/program_a_fifo` (если его нет) и открывает его на запись — открытие блокирующее: B ждёт, пока A откроет канал на чтение;
- следит за процессом A (`waitpid` с `WNOHANG`) и завершается с сообщением, если A умерла;
- переводит терминал в неканонический режим (`termios`, модуль `Terminal`), читает клавиши по одной и отправляет их в канал уже открытым дескриптором (`utils::ipc_worker`);
- `q`/`Q` — выход (в A не отправляется).

По заданию также планируются: поля для ввода параметров A (в варианте 3 — цвет фона) и передача их при запуске, отправка команды `cmd=color:<имя>`.

Статус: запуск A, создание канала, слежение за процессом и отправка команд реализованы; передача параметров A — в планах.

### Программа C — `program_c`

Программа мониторинга A: находит процесс, проверяет аргументы запуска, пишет лог и инжектирует команды.

- ищет в `/proc` процесс с именем `program_a`, сканируя `/proc/<pid>/comm`;
- читает `/proc/<pid>/cmdline`, пересобирает `argv` и проверяет аргументы запуска статическим парсером `Terminal::parseBackgroundColor(std::vector<std::string>)`; при неверных параметрах сообщает об ошибке и выходит с кодом 1;
- пишет собственный лог `program_c.log`: время запуска A (по метке времени каталога `/proc/<pid>`) и время её завершения (проверка живости через `kill(pid, 0)` каждые 100 мс);
- в отдельном потоке «инжектирует» команды: дочитывает новые строки `program_a.log`, и при появлении `key=<триггер>` отправляет в FIFO дополнительную команду `key=d` (триггер — `b`, зашит в коде);
- после завершения A ждёт нажатия клавиши в своём терминале (`q` — выход); raw-режим не включается, поэтому клавишу нужно подтверждать Enter;
- завершается с кодом 1 и понятным сообщением, если A не найдена, `/proc` недоступен или аргументы запуска некорректны.

В планах (по заданию): ждать появления A, если она ещё не запущена, и корректно переживать рестарт A; для Windows потребуется отдельный скрипт `program_c.au3` (AutoIt).

Статус: поиск A, проверка аргументов, мониторинг с логом и инъекция реализованы; ожидание появления A — в планах.

## Архитектура взаимодействия

Целевая схема (по заданию): запуск процесса, именованный канал (FIFO), файловые логи и мониторинг через `/proc`.

```text
program_b ── posix_spawn + alacritty ─────────────────────────────► program_a
program_b ── mkfifo + open(O_WRONLY) ──► /tmp/program_a_fifo
program_b ── key=<символ> ─────────────► /tmp/program_a_fifo ─────► program_a
program_c ── key=d (инъекция) ─────────► /tmp/program_a_fifo ─────► program_a
program_c ── мониторинг /proc/<pid> (comm, cmdline, kill) ────────► program_a
program_a ── program_a.log ──────────────────────────────────────► program_c (чтение новых строк)
program_c ── program_c.log (время запуска и завершения A)
```

Сейчас работают все связи схемы, кроме одной: B не передаёт A параметры запуска (A всегда стартует с чёрным фоном). Актуальное состояние — в разделе [Статус реализации](#статус-реализации).

## Требования

- **Linux** — реализация использует POSIX-механизмы (`termios`, FIFO, `signals`, `spawn`) и `/proc`; варианты для Windows — по заданию в планах (Win32 API, AutoIt).
- **CMake ≥ 3.21** — из-за версии схемы `CMakePresets.json` (version 3).
- **Компилятор с C++20**: GCC 13+ или Clang 17+ (требуется `std::format`, `std::chrono` с зонами).
- **Ninja** — генератор для пресетов сборки.
- **alacritty** — эмулятор терминала, в котором B запускает A (путь `/usr/bin/alacritty` зашит в коде). Для ручного запуска A не требуется.
- **tzdata** — для `std::chrono::zoned_time` (в обычном дистрибутиве Linux уже установлен).
- Опционально: `clang-format` (форматирование), `clangd` (навигация по коду — `.clangd` уже указывает на `out/gcc-debug`).

## Запуск

### Программа A (ручной запуск)

Из каталога `lab1`: лог `program_a.log` создаётся в текущем каталоге.

```bash
./out/gcc-debug/bin/program_a                # фон по умолчанию (чёрный)
./out/gcc-debug/bin/program_a --color green  # старт с зелёным фоном
```

Нажимайте `d`/`r`/`g`/`y`/`b` для смены цвета фона, `q` — выход. Программа работает в цикле событий: ждёт событие (клавишу или команду из FIFO), обрабатывает, обновляет экран, снова ждёт.

FIFO открывается один раз при запуске. Если канал не существовал в этот момент, приём команд работать не будет — для управления извне создайте его заранее:

```bash
mkfifo /tmp/program_a_fifo 2>/dev/null
```

Если писатель канала отключится (например, B завершится), A продолжит работу и примет новое подключение.

### Программа B (запускает A и создаёт канал)

Из каталога `lab1`, при работающем графическом окружении (нужен alacritty):

```bash
./out/gcc-debug/bin/program_b
```

B создаёт канал сам, поэтому отдельный `mkfifo` для этого сценария не нужен. Порядок действий внутри B: найти `program_a` рядом со своим бинарником → запустить её в alacritty → создать FIFO и открыть его на запись (B ждёт, пока A откроет канал на чтение) → читать клавиши в raw-режиме и отправлять `key=<символ>`.

Клавиши `d`/`r`/`g`/`y`/`b`, нажатые в B, уходят в канал и применяются программой A; `q`/`Q` — выход из B. Если A завершилась (например, `q` внутри A), B сообщит об этом и завершится; если читатели канала исчезли, B сообщит об ошибке записи.

### Программа C

Из каталога `lab1`, после того как A уже запущена (C ищет её один раз при старте):

```bash
./out/gcc-debug/bin/program_c
```

C находит `program_a` в `/proc`, проверяет её аргументы запуска, пишет `program_c.log` и в фоновом потоке следит за `program_a.log`. Триггер инъекции — `b`: увидев `key=b`, C отправляет в канал `key=d`. После завершения A C пишет время окончания и ждёт нажатия клавиши: `q` + Enter — выход. Если A не запущена, печатает `ERROR: program_a is not found` и возвращает код 1.

## Формат логов

**`program_a.log`** (создаётся в текущем каталоге; при запуске из `lab1` — `lab1/program_a.log`) — по одной строке на событие:

```text
2026-10-25 13:26:54 key= 
2026-10-25 13:26:56 key=r
2026-10-25 13:26:59 key=b
2026-10-25 13:27:08 key=b
2026-10-25 13:27:08 key=d
2026-10-25 13:27:25 exit
```

Формат строки: `ГГГГ-ММ-ДД ЧЧ:ММ:СС key=<клавиша>`. Строка `key=` (после знака равенства стоит пробел) пишется при старте — это применение начального цвета, когда клавиша ещё не нажата. При завершении программы дописывается строка `ГГГГ-ММ-ДД ЧЧ:ММ:СС exit`.

Клавиши, полученные через FIFO, обрабатываются и логируются так же, как нажатые локально, — по логу источник не отличается. Клавиши вне набора `d`/`r`/`g`/`y`/`b` игнорируются и в лог не попадают. Пара `key=b` → `key=d` в примере выше — работа инъекции программы C.

**`program_c.log`** (создаётся в текущем каталоге) — время запуска и завершения A:

```text
2026-10-25 13:27:03 Process `program_a` is running in 2026-10-25 13:26:55
2026-10-25 13:27:25 Process `program_a` is ending in 2026-10-25 13:27:25
```

Первая метка времени в строке — момент записи события в лог, вторая — время запуска (по метке времени каталога `/proc/<pid>`, точность около секунды) или время завершения A. Время — локальное.

Оба лога дописываются в конец файла и не удаляются между запусками (очищайте вручную, если нужен «чистый» лог).

## Протокол команд (FIFO)

Для управления программой A из других процессов используется именованный канал `/tmp/program_a_fifo`. Программа A держит его открытым (неблокирующее чтение в фоновом потоке, ожидание через `poll`); пришедшие команды обрабатываются так же, как нажатия клавиш.

Команды — текстовые, по одной на сообщение:

| Команда            | Действие                                                          | Статус          |
| ------------------ | ----------------------------------------------------------------- | --------------- |
| `key=<символ>`     | обрабатывается как нажатие клавиши (например, `key=b` — синий фон) | ✅ реализовано   |

Пример отправки команд из оболочки (программа A должна быть запущена). Канал нужно держать открытым — так данные не потеряются:

```bash
mkfifo /tmp/program_a_fifo 2>/dev/null

exec 3>/tmp/program_a_fifo     # открыть канал на запись
printf 'key=b' >&3             # синий фон
printf 'key=r' >&3             # красный фон
exec 3>&-                      # закрыть, когда команды отправлены
```

> [!NOTE]
> Отправка одной командой (`echo -n 'key=b' > /tmp/program_a_fifo`) может не сработать: если писатель закрыл канал раньше, чем A успела прочитать данные, A видит одновременно `POLLIN` и `POLLHUP` и уходит в ожидание нового подключения. B держит канал открытым, поэтому его команды доходят всегда.

Особенности работы с каналом:

- A открывает FIFO один раз при старте и не переоткрывает его: если канала не было в этот момент, приём команд не заработает без перезапуска A;
- B создаёт канал сам и открывает его на запись блокирующе — ждёт читателя; C открывает канал на запись в потоке инъекции, поэтому тоже требует запущенную A;
- если читатели отключатся во время работы, запись вернёт `EPIPE` (SIGPIPE игнорируется): B прервёт работу с сообщением, C — выведет ошибку в потоке инъекции;
- A переживает отключение писателя и ждёт новое подключение;
- неизвестные команды и сообщения с неподдерживаемым форматом игнорируются.

## Демонстрационный сценарий

1. В терминале 1 запускается B — он открывает A в окне alacritty и создаёт канал.
2. В терминале 2 запускается C — находит A, проверяет аргументы и пишет в `program_c.log` время запуска.
3. B отправляет A команды: нажатия `d`/`r`/`g`/`y`/`b` уходят через FIFO, A меняет цвет фона и пишет `program_a.log`.
4. При нажатии `b` C видит новую строку `key=b` в логе A и инжектирует `key=d` — в логе A появляется дополнительное событие.
5. A завершается (`q`); C фиксирует в `program_c.log` время завершения и ждёт нажатия клавиши; B сообщает, что A умерла, и выходит.

Сейчас выполнимы все шаги. Не реализована только передача параметров A при запуске: на шаге 1 A стартует с цветом по умолчанию. Ожидание появления A в C и варианты для Windows — в разработке.

## Ограничения и известные особенности

- B не передаёт A параметры запуска — A всегда стартует с цветом по умолчанию. Сам B принимает `--color`, но применяет его к терминалу А.
- Инъекция зашита в коде: триггер — `b`, отправляемая команда — `key=d`. Она срабатывает на каждое появление `key=b` в логе A, в том числе если `b` нажата непосредственно в окне A.
- C ищет A один раз при старте; если A перезапустить, C нужно запустить заново. После завершения A C ждёт нажатия клавиши.
- C не включает raw-режим: клавиши вводятся с подтверждением Enter.
- A открывает канал один раз при старте, поэтому канал должен существовать до её запуска. В сценарии с B это обеспечивает сам B (создаёт FIFO сразу после `posix_spawn`).
- Одноразовая запись в канал (`echo ... > fifo`) может потеряться: если писатель закрывает канал раньше, чем A прочитала данные, A видит одновременно `POLLIN` и `POLLHUP` и уходит в ожидание нового подключения. Надёжно — держать канал открытым (так делает B).
- Путь `/usr/bin/alacritty` зашит в коде B.
- Время запуска A в `program_c.log` приблизительное: берётся метка времени каталога `/proc/<pid>` (точность около секунды).
- Смена цвета требует эмулятора терминала с поддержкой OSC 11 (alacritty, kitty, xterm и т. п.).

## Диагностика

| Симптом | Причина | Что делать |
| ------- | ------- | ---------- |
| `ERROR: program_a is not found` (C) | A не запущена или уже завершилась | запустить A (или B) и запустить C заново |
| B завис после запуска A | канал открыт на запись, но читателя нет (A не открыла FIFO) | не удалять канал; перезапустить связку B → A |
| `ERROR: all readers is dead!` (B) | A завершилась, запись в канал невозможна | перезапустить B (и A) |
| `ERROR: Failed to open FIFO channel!` | канала нет или нет читателя | запустить связку через B (он создаёт канал) и повторить C |
| Команда из shell не применяется | одноразовая запись: писатель закрылся раньше чтения | держать канал открытым (`exec 3>...`, см. [Протокол команд](#протокол-команд-fifo)) |
| Цвет фона не меняется | терминал не поддерживает OSC 11 | использовать alacritty/kitty/xterm; в связке A и так запускается в alacritty |
| C не реагирует на клавиши | raw-режим не включён | нажимать клавишу и Enter |
| `terminate called ... std::invalid_argument` (A) | неверные аргументы (`--color` с неизвестным именем) | использовать `black`/`red`/`green`/`yellow`/`blue` |
| `ERROR: Failed to open the file!` | нет прав на запись лога в текущем каталоге | запускать из каталога с правом записи (например, `lab1`) |
