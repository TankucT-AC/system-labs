Курс «Системное программное обеспечение», 2026 год. Вариант 1 — **калькулятор**.

Консольная программа-калькулятор на C, разбитая на модули: **ядро** (`calc`) — чистые функции `add`/`sub`/`mul`/`div` и диспетчер `op`, не знающий о вводе-выводе, собирается в статическую библиотеку `libcalclib.a`; **интерфейс** (`main.c`) — точка входа `calc_app`, читающая три числа со стандартного потока и печатающая результат. Отдельный бинарник `test_calc` проверяет ядро 14 проверками (линкуется только с ядром, без `main.c`) и подключён к CTest. Сборка — тремя способами: вручную, через Makefile и через CMake. Собирается в Linux (GCC → ELF) и Windows (MSVC → COFF/PE); сравнение артефактов двух платформ — в [отчёте](report/lab2_report.pdf).

## Быстрый старт

```bash
cd lab2
cmake --preset gcc-debug && cmake --build out/gcc-debug
```

```bash
echo "2 3 0" | ./out/gcc-debug/bin/calc_app    # 2 + 3 → Result: 5
ctest --test-dir out/gcc-debug                  # прогон модульных тестов
```

Программа читает со стандартного ввода три целых числа — два операнда и код операции — и печатает `Result: <значение>` или сообщение об ошибке с ненулевым кодом возврата.

## Возможности

- **Разделение ответственности**: ядро (`src/calc.{h,c}`) не знает о вводе-выводе; вся работа с пользователем — в `main.c`.
- **Статическая библиотека**: ядро собирается CMake в `libcalclib.a` (`add_library(calclib STATIC)`).
- **Три способа сборки**: вручную (`gcc -c` + линковка), через Makefile (`make`/`make clean`) и через CMake-пресеты.
- **Кроссплатформенность**: один исходный код собирается в Linux (GCC → ELF) и Windows (MSVC → COFF/PE).
- **Обработка ошибок**: нечисловой ввод, неверный код операции и деление на ноль — понятное сообщение и код возврата 1.
- **Модульные тесты**: собственный мини-фреймворк `ASSERT_EQ`/`RUN_TEST`, 14 проверок, интеграция с CTest (`add_test`).
- **Изучение артефактов**: объектные файлы и библиотека исследуются утилитами `nm`, `objdump -t`, `readelf -s`, `ar t` (разбор — в [отчёте](report/)).

## Компоненты

### Ядро — `src/calc.{h,c}` → `libcalclib.a`

Чистые функции и диспетчер операции по коду. Коды операций объявлены в `calc.h`:

| Код | Константа | Операция              |
| --- | --------- | --------------------- |
| `0` | `ADD`     | сложение              |
| `1` | `SUB`     | вычитание             |
| `2` | `DIV`     | целочисленное деление |
| `3` | `MUL`     | умножение             |

- `div(a, b)` при `b == 0` возвращает маркер `NAN` (преобразованный к `int`); прикладной слой отсекает деление на ноль раньше, поэтому маркер наружу не выходит;
- `op(a, b, код)` — `switch`-диспетчер; неизвестный код возвращает `0`.

### Интерфейс — `main.c` → `calc_app`

Читает со стандартного потока строку вида `a b код_операции` (три целых числа через пробел), валидирует и печатает результат.

**Коды возврата**

| Код | Ситуация                                    | Сообщение                      |
| --- | ------------------------------------------- | ------------------------------ |
| `0` | успешный расчёт                             | `Result: <значение>`           |
| `1` | введены не числа                            | `error: uncorrect input!!!`    |
| `1` | код операции вне допустимого диапазона      | `error: uncorrect operator!!!` |
| `1` | деление на ноль (код `2` при `b == 0`)      | `error: division by zero!!!`   |

### Тесты — `test/test_calc.c` → `test_calc`

Автономный исполняемый файл с мини-фреймворком: `ASSERT_EQ` печатает `[FAIL]` (в `stderr`) по каждому провалившемуся случаю, `RUN_TEST` печатает `[ OK ]` по тест-функции без провалов; в конце — итоговая строка и код возврата `1`, если есть провалы.

| Группа     | Случаи                                                                  | Проверок |
| ---------- | ----------------------------------------------------------------------- | -------- |
| `test_add` | положительные, отрицательные, нулевой операнд                           | 3        |
| `test_mul` | обычное/знаковое умножение, ноль, большие числа (переполнение)          | 4        |
| `test_sub` | положительные, отрицательные, равные операнды                           | 3        |
| `test_div` | целочисленное деление, отрицательные, нулевой делимый, деление на ноль  | 4        |

Тесты линкуются **только с ядром** (`target_link_libraries(test_calc calclib)`) — без `main.c`, как требует задание.

## Архитектура

```text
main.c ────── op(a, b, код операции) ──────► libcalclib.a (src/calc.c: add/sub/mul/div/op)
test_calc.c ─ op(...) ─────────────────────► libcalclib.a (линковка без main.c)

CMake ── add_library(calclib STATIC) ───────► out/<preset>/src/libcalclib.a
CMake ── add_executable + target_link_libraries ► out/<preset>/bin/calc_app, bin/test_calc

Makefile ── gcc main.o calc.o ──────────────► calc_make_app (прямая линковка, без архива)
```

## Требования

- **Linux** — основной стек: GCC, GNU binutils (`nm`, `objdump`, `readelf`, `ar`), GNU Make, Ninja.
- **Windows** — MSVC: Visual Studio или Build Tools (инструменты 14.52 проверены) + CMake; артефакты исследуются `dumpbin`/`lib`.
- **CMake ≥ 3.20** — из-за версии схемы `CMakePresets.json` (version 3).
- **Компилятор C11**: GCC или Clang.
- **Ninja** — генератор для пресетов сборки.
- **GNU Make + gcc** — для ручной сборки через Makefile.
- Опционально: `binutils` (`nm`, `objdump`, `readelf`, `ar` — для изучения артефактов), `clang-format`, `clangd`.

## Сборка

Все команды выполняются из каталога `lab2`.

### Вручную

```bash
gcc -I. -c main.c
gcc -I. -c src/calc.c
gcc main.o calc.o -o calc_manual_app

# вариант со статической библиотекой:
ar rcs libcalc.a calc.o
gcc main.o -L. -lcalc -o calc_manual_app
```

### Через Makefile

```bash
make          # all: main.o, calc.o → calc_make_app
make clean    # удаляет *.o, *.a и файл calc
```

### Через CMake (рекомендуется)

```bash
# Debug-сборка (GCC + Ninja)
cmake --preset gcc-debug
cmake --build out/gcc-debug

# Release-сборка (Clang + Ninja)
cmake --preset clang-release
cmake --build out/clang-release
```

Исполняемые файлы — в `out/<preset>/bin/`, библиотека — в `out/<preset>/src/libcalclib.a`. Что CMake выполняет внутри (компиляция, `ar qc` + `ranlib`, компоновка), — см. таблицу в [отчёте](report/lab2_report.pdf).

### Windows (MSVC)

В среде разработчика Visual Studio (x64):

```bat
cmake --preset msvc-debug
cmake --build out\msvc-debug --config Debug
```

Библиотека — `out\msvc-debug\src\calclib.lib`, бинарники CMake — в `out\msvc-debug\bin\`. Объектный файл и приложение можно собрать вручную:

```bat
cl /c src\calc.c
cl main.c calc.obj
```

`cl` без опции `/Fe` именует исполняемый файл по первому переданному `.c`-файлу, поэтому бинарник называется `main.exe`, а не `calc_app.exe`.

## Запуск

### Калькулятор

```bash
echo "2 3 0"  | ./out/gcc-debug/bin/calc_app    # сложение → Result: 5
echo "1 12 1" | ./out/gcc-debug/bin/calc_app    # вычитание → Result: -11
echo "10 4 2" | ./out/gcc-debug/bin/calc_app    # деление (целочисленное) → Result: 2
echo "5 100 3"| ./out/gcc-debug/bin/calc_app    # умножение → Result: 500

echo "5 0 2"  | ./out/gcc-debug/bin/calc_app    # error: division by zero!!!
echo "1 2 9"  | ./out/gcc-debug/bin/calc_app    # error: uncorrect operator!!!
echo "abc"    | ./out/gcc-debug/bin/calc_app    # error: uncorrect input!!!
```

Формат ввода: три целых числа через пробел — `операнд_1 операнд_2 код_операции`. Коды операций — в таблице [Компоненты](#компоненты).

### Тесты

```bash
ctest --test-dir out/gcc-debug          # через CTest
./out/gcc-debug/bin/test_calc           # прямой запуск
```

Текущий результат: 13 из 14 проверок проходят; тест `test_calc` помечается `Failed` из-за намеренного кейса переполнения `int` в `test_mul` (см. [Ограничения](#ограничения-и-известные-особенности)).

## Изучение артефактов

```bash
nm out/gcc-debug/src/libcalclib.a        # символы членов архива (T/U)
ar t out/gcc-debug/src/libcalclib.a      # список членов архива
readelf -s out/gcc-debug/src/libcalclib.a # полная таблица символов

gcc -I. -c src/calc.c && nm calc.o       # объектный файл ручной сборки
objdump -t calc.o                        # таблица символов с секциями
```

Windows (MSVC) — те же данные из COFF/PE-артефактов:

```bat
dumpbin /symbols calc.obj
dumpbin /headers main.exe
lib /list out\msvc-debug\src\calclib.lib
```

Буквы `nm`: `T` — определённый символ в секции `.text`, `U` — неопределённый (внешняя ссылка, разрешается при компоновке); в COFF-таблице то же — строки `External` (определён) с номерами секций `SECT<n>`. Подробный разбор всех листингов — в [отчёте](report/lab2_report.pdf).

## Ограничения и известные особенности

- **Переполнение `int`** в умножении не контролируется (UB по стандарту). Тест-кейс `op(50000, 50000, MUL)` в `test_mul` намеренно оставлен падающим как демонстрация: на x86-64 возвращается `-1794967296` вместо `2500000`, поэтому итог прогона — `Провалено: 1`, а `ctest` помечает тест как `Failed`.
- **Маркер деления на ноль**: `div` возвращает `NAN`, преобразованный к `int` — формально UB и платформозависимо; в приложении деление на ноль отсекается в `main.c` до вызова ядра.
- **Частичный ввод** (одно-два числа вместо трёх) не отсекается: проверка `!scanf(...)` срабатывает только при нуле успешно прочитанных элементов, недочитанные переменные остаются неинициализированными.
- Код операции `4` проходит проверку диапазона (`0..4`), но `op` поддерживает только `0..3` — для `4` возвращается `Result: 0`.
- `op` для неизвестного кода возвращает `0`, а не сигнал об ошибке.
- **Целочисленное деление**: `10 / 4` даёт `2` (дробная часть отбрасывается).
- `make clean` удаляет `*.o`, `*.a` и файл `calc`, но не бинарник `calc_make_app` — удалите его вручную при необходимости.
- Сообщения об ошибках печатаются в `stdout` (а не в `stderr`).
- Под Windows проект собран (вручную через `cl` и через CMake), артефакты исследованы ([`dumps_output.txt`](dumps_output.txt)); демонстрационные прогоны и `ctest` выполнены в Linux.

## Диагностика

| Симптом                                     | Причина                                         | Что делать                                              |
| ------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------- |
| `undefined reference to 'mul'` при сборке   | определение `mul` удалено из `calc.c`           | вернуть реализацию (демонстрация из отчёта, п. 7)       |
| `ctest`: `test_calc ...***Failed`           | намеренный кейс переполнения `int` в `test_mul` | ожидаемое поведение (см. [Ограничения](#ограничения-и-известные-особенности)) |
| `error: uncorrect input!!!`                 | введены не числа                                | вводить три целых числа через пробел                    |
| `error: uncorrect operator!!!`              | код операции вне `0..4`                         | использовать коды `0..3`                                |
| `error: division by zero!!!`                | `b == 0` при коде операции `2` (деление)        | передать ненулевой делитель                             |
| `make: *** No rule to make target`          | запуск не из каталога `lab2`                    | перейти в каталог `lab2`                                |
| `CMake Error` при `--preset`                | нет Ninja или CMake < 3.20                      | установить `ninja`, обновить `cmake`                    |
